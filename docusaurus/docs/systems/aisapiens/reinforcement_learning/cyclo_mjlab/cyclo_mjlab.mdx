# Cyclo MJLab

Cyclo MJLab is the MuJoCo-based environment for training AI Sapiens K1 policies in simulation.
Built on [MJLab](https://github.com/mujocolab/mjlab) and [MuJoCo](https://mujoco.org/), it provides reinforcement learning environments, task configurations, and motion-processing tools for K1 locomotion and motion imitation.

Cyclo MJLab currently provides:

- **Velocity** for flat-ground velocity-tracking locomotion.
- **BeyondMimic** for tracking Dance1 and Dance2 reference motions; its task IDs use `Cyclo-BeyondMimic-*`.
- **SuperMimic and BlinkMimic** for world-model-based motion tracking.

The BeyondMimic workflow uses the same Sim2Real deployment process as Cyclo Lab. SuperMimic and BlinkMimic also export ONNX policies and deployment settings.
For robot-side deployment after training, follow [How to Deploy Your Own Cyclo Lab-Trained Policy](/docs/systems/aisapiens/development_guide/sim2real/#how-to-deploy-your-own-cyclo-lab-trained-policy).

## Set Up the Docker Container

Run Cyclo MJLab inside the provided Docker container.
The container includes Python, MJLab, MuJoCo, the required GPU configuration, and the Python dependencies used by the training and playback scripts.
A separate Conda or host Python environment is not required.

Install these on the host PC first:

- Docker Engine with Docker Compose.
- An NVIDIA GPU with an appropriate NVIDIA driver.
- NVIDIA Container Toolkit.

Clone Cyclo MJLab with its submodules:

```bash
git clone --recurse-submodules https://github.com/ROBOTIS-GIT/cyclo_mjlab.git
cd cyclo_mjlab
```

If the repository was cloned without submodules, initialize them before starting the container:

```bash
git submodule update --init --recursive
```

Start and enter the container:

```bash
./docker/container.sh start
./docker/container.sh enter
```

The start command builds the Docker image when it is not already available, starts the container, and verifies the Python and NVIDIA GPU environment.

Inside the container, the repository is mounted at:

```text
/workspace/cyclo_mjlab
```

Useful host-side commands:

| Command | Use |
| --- | --- |
| `./docker/container.sh start` | Build the image if needed, initialize submodules, and start the container. |
| `./docker/container.sh enter` | Open a shell inside the running container. |
| `./docker/container.sh stop` | Stop the container. |
| `./docker/container.sh logs` | Follow the container logs. |
| `./docker/container.sh clean` | Remove the container and image while preserving cache volumes. |

:::note
The project source and `logs/` directory are shared with the host PC, so training results remain available after the container is stopped or removed.
:::

:::info
The 1.1.x environment uses Python 3.12 and MJLab 1.6.1 for all four learning methods.
:::

## List Available Tasks

Run the task-listing script inside the container to see the task IDs supported by the current source checkout:

```bash
python scripts/list_envs.py
```

Examples of available tasks include:

```text
Cyclo-BeyondMimic-K1-Rev2-Dance1
Cyclo-BeyondMimic-K1-Rev2-Dance2
Cyclo-Velocity-Flat-K1-Rev2-v0
Cyclo-SuperMimic-GenCoord-K1-Rev2-001
Cyclo-SuperMimic-MaxCoord-K1-Rev2-001
Cyclo-BlinkMimic-K1-Rev2-001
```

Use `--keyword` to filter the list. For example, list only the Mimic tasks with:

```bash
python scripts/list_envs.py --keyword Mimic
```

Use the displayed task ID as the first positional argument to `train.py` or `play.py`.

## Choose a Viewer

BeyondMimic and Velocity accept `--viewer auto`, `--viewer native`, or `--viewer viser`.
The default `auto` mode uses the native MuJoCo viewer when a desktop display is available and otherwise starts the browser-based Viser viewer.

To select a viewer explicitly, append `--viewer native` or `--viewer viser` to a `play.py` command.

SuperMimic and BlinkMimic default to `viser`; BlinkMimic does not provide a native MuJoCo viewer.

Use `native` when running locally with a desktop display.
Use `viser` for a headless or remote environment, and open the URL printed by `play.py` in a web browser.

Use [Motion Tracking](../motion_tracking) to compare BeyondMimic and SuperMimic (world model), then [prepare the motion](../motion_preparation).
