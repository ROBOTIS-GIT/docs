# SuperMimic (World Model)

SuperMimic learns dynamics from simulator transitions and trains a tracking policy through imagined rollouts. Cyclo Lab calls the [official HybridRobotics SuperMimic](https://github.com/HybridRobotics/SuperMimic) learners with states collected directly in Isaac Lab. It uses the same Isaac runtime as [BeyondMimic PPO](./mimic), with different checkpoints and deployment contracts.

:::info[Development branch]
This guide describes Cyclo Lab `feature-supermimic`, including native implementation `d9ab0766cedade0966b01f85ac65737b8fc48af4`. It is not the current `main` release. Bounded PhysX learning, fresh-process local play, and resumed updates have been checked. Long-run tracking quality, compiled execution and robot deployment have not been validated.
:::

## Install

Use a separate [Cyclo Lab](https://github.com/ROBOTIS-GIT/cyclo_lab) checkout on `feature-supermimic`. Follow the [Cyclo Lab setup](./) to build, start, and enter its Isaac Sim 6.2 / Isaac Lab 3.0 Docker environment. This native integration uses Python 3.12; do not add the upstream MJLab Python 3.13 runtime to Cyclo Lab.

The RSL-RL extra supplies the matching Torch, normalization, and TensorDict dependencies. If it was omitted, install the branch's pinned requirements inside the container:

```bash
uv pip install --python /opt/isaaclab-venv/bin/python -r requirements/supermimic.txt
```

The current SuperMimic launcher selects PhysX. Newton overrides are rejected. Fixed dynamics and zero context are required; material/friction, COM, home-offset and push randomization overrides are rejected. The existing PPO presets and commands remain available.

## Prepare Motion

Follow [common motion preparation](../motion_preparation). Both methods can consume the same existing named **50 Hz Cyclo Lab NPZ** without another conversion. The selector's `--motion-file` validates names, arrays, FPS and quaternion metadata before either learner starts; SuperMimic also checks against the live articulation.

Input must include unique `joint_names` and `body_names`, all 23 matching K1 joints, body coverage for the articulation, consistent finite SI world-frame arrays, unit quaternions, and explicit `quaternion_order` (or `quat_order`). The shared loader reorders named columns and converts declared quaternions to Isaac's xyzw; the learner bridge converts root quaternions to wxyz once. Missing/conflicting conventions, duplicate/unknown joints, missing required bodies, malformed arrays and non-50 Hz input are rejected. No resampling or rewriting occurs. This does not establish compatibility with MJLab's different body/frame contract.

SuperMimic additionally checks every frame and moving body against supported K1 FK and source-defined COM/link-origin velocity profiles. Canonical root link twists are computed in memory. Arrays must be real and finite after float32 conversion. Missing producer/backend labels remain `unspecified`; physical agreement does not establish provenance. Source bytes are preserved.

## Select and Train

Run inside the container from the repository root. Existing `Cyclo-Mimic-K1-Rev1-Dance1/2` PPO task IDs remain supported, and `Cyclo-BeyondMimic-*` aliases select the same configurations. Both `train.py` and `play.py` accept optional `--algorithm beyondmimic|supermimic` and infer the method from recognized task IDs. Conflicting selections fail. Historical `mimic.py --method` and direct RSL-RL launchers remain supported. Select explicitly as follows:

```bash
python scripts/reinforcement_learning/train.py --algorithm beyondmimic \
  --task Cyclo-BeyondMimic-K1-Rev1-Dance1 \
  --motion-file source/cyclo_lab/data/motions/K1_rev1/dance1/dance1.npz \
  --num_envs 4096 --headless physics=isaacsim_physx
```

For native SuperMimic GenCoord tracking, check GPU availability and choose an environment count that fits its memory:

```bash
python scripts/reinforcement_learning/train.py --algorithm supermimic \
  --task Cyclo-SuperMimic-K1-Rev1-Dance1 \
  --motion-file source/cyclo_lab/data/motions/K1_rev1/dance1/dance1.npz \
  --num-envs 32 --iterations 1000 --eager --headless \
  --output logs/supermimic/k1-dance1
```

Replace the motion path with your validated reference. `--eager` disables compilation and graph capture while retaining the same losses, rollout gradients and optimizers; this is the verified execution mode. Compiled learning is not validated here. The runner collects real Isaac transitions, updates the world model and optimizes the actor through imagined dynamics. Checkpoints are written as `model_<iteration>.pt` under the output directory.

Bounded verification used two environments and tiny batches: both world-model and actor parameters changed, metrics were finite, and checkpoints saved/reloaded. The existing PPO selector also passed a short real PhysX update on the same original reference. These checks do not demonstrate convergence or a good tracking policy.

## Play and Resume

Use the local v2 checkpoint from your run. Every completed iteration saves final model, normalizer and optimizer state. Replace the example path with your actual file:

```bash
python scripts/reinforcement_learning/play.py --algorithm supermimic \
  --checkpoint logs/supermimic/k1-dance1/model_1000.pt \
  --num-envs 1 --play-steps 1000 --eager --headless

python scripts/reinforcement_learning/train.py --algorithm supermimic \
  --checkpoint logs/supermimic/k1-dance1/model_1000.pt \
  --iterations 100 --eager --headless --output logs/supermimic/k1-dance1-continue
```

`cyclo-supermimic-isaac-v2` validates the task, motion digest, robot/action contract, physical model and exact timestep **and decimation** before simulation. Repeat supported nondefault physical overrides when loading. A relocated motion may be specified with `--motion-file`, but its digest must match. Old v1 files are rejected. Local play requires no W&B account or synchronization.

Continuation restores learned parameters, normalizers and optimizer state into fresh simulator, replay and RNG state. It is not exact trajectory resume. Inference does not restore optimizers. These files are incompatible with PPO checkpoints and MJLab inference bundles.

Bounded evidence includes 69 tests, five real PhysX WM/actor updates, exact final-state reload, a fresh-process sixth update, eight inference steps and a legacy PPO iteration. WM parameters stay frozen during actor updates. Interactive playback, compiled performance, convergence and robot export remain unverified; no GitHub check runs establish CI green.

## Supported Scope and Deployment

The native port supports GenCoord K1, privileged `rep_state`, history length 1, one clip/encoder and fixed dynamics with zero context. MaxCoord, proprio/history actors, motion-to-velocity latent behavior cloning, official return sampling, multi-task/multi-clip and robot export are not integrated. It retains the existing K1 asset and uses a separate tracking configuration; PPO settings remain unchanged.

There is no validated SuperMimic-to-K1 Sim2Real export/controller contract. A world-model checkpoint is not the [BeyondMimic](./mimic) `policy.onnx` and `sim2real.yaml` pair. Observation history, normalization, action transform, timestep, joint order and reference format need independent validation before robot use. See the [method comparison](../motion_tracking) when choosing a workflow.
