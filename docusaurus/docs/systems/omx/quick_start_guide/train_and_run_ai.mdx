### What is ACT?

You show OMX a task at least 50 times with the leader arm. ACT learns from your tries, and then OMX tries the task by itself.

ACT is an imitation learning model. It looks at the camera picture and the arm's angles, and plans the next moves in the way your tries showed it.

ACT is a good model for a first dataset. It is small, and it learns on the one graphics card in your PC.

The clip shows one of our runs that worked. Your result can be different: it depends on your tries, the camera and the light.

This is imitation learning with ACT, done once with Cyclo Intelligence. Start after [Bringup](./move_omx.mdx).

<StepTab id="install-cyclo-intelligence" title="Install Cyclo Intelligence" label="Install">

Cyclo Intelligence records what you show OMX, and later runs the AI model. You install it once.

### A. Install

In a PC terminal:

```bash
curl -fsSL https://raw.githubusercontent.com/ROBOTIS-GIT/cyclo_intelligence/main/install.sh | bash
```

When it is done, it shows where it put Cyclo Intelligence. On your PC, your user name is in place of `robotis`.

<TutorialMedia
  label="The terminal after the install command. It downloads Cyclo Intelligence with git. The line [install] Installed Cyclo Intelligence at: /home/robotis/cyclo_intelligence is marked in red."
  src="/img/systems/omx/quick_start_guide/train_and_run_ai/install_cyclo_intelligence.webp"
  shape="free"
  width={760}
/>

The last lines also say that the model sources were not downloaded. Download the one this guide uses, LeRobot. Step 4 builds the AI program from it.

```bash
cd ~/cyclo_intelligence
git submodule update --init -- \
  cyclo_brain/sdk/zenoh_ros2_sdk \
  cyclo_brain/policy/lerobot/lerobot
```

The last line starts with `Submodule path 'cyclo_brain/policy/lerobot/lerobot': checked out`.

### B. Start it and enter its container

```bash
cd ~/cyclo_intelligence
./docker/container.sh start
./docker/container.sh enter
```

It downloads Cyclo Intelligence, then opens a terminal inside its container. Wait until you can type again. If it asks for your password, type it.

### C. Check the Zenoh setting

In the Cyclo container, check the [Zenoh](/docs/systems/omx/specifications/software#middleware) setting:

```bash
grep ZENOH_CONFIG_OVERRIDE ~/.bashrc
```

### You should see

The first line, in the red box, is the setting. The second line starts with # and does nothing. That is fine.

<TutorialMedia
  label="The terminal after the check command. The first line, export ZENOH_CONFIG_OVERRIDE='transport/shared_memory/enabled=true', is marked in red. The second line starts with # and does nothing."
  src="/img/systems/omx/quick_start_guide/train_and_run_ai/check_zenoh_setting.webp"
  shape="free"
  width={760}
/>

Then type `exit` and press **Enter** to leave the container.

<NotGood id="install-cyclo-intelligence-fix">

| You see | Do this |
| --- | --- |
| `curl: command not found` | Paste `sudo apt install curl`, then do part A again. |
| `Refusing to modify an existing Cyclo checkout` | It was downloaded before. Update it instead: paste `cd ~/cyclo_intelligence && git pull --ff-only && git submodule update --init -- cyclo_brain/sdk/zenoh_ros2_sdk cyclo_brain/policy/lerobot/lerobot`. Then do part B. In Step 4, part D, add `--build` once: `./docker/container.sh start-lerobot --build`. |
| `no space left on device` | Free some disk space. Then do part B again. |
| No line in part C | Paste <code>echo "export ZENOH_CONFIG_OVERRIDE='transport/shared_memory/enabled=true'" >> ~/.bashrc</code>, then `source ~/.bashrc`. |

</NotGood>

  <summary>How does it work?</summary>

  Cyclo Intelligence runs in its own Docker container, next to the robot software. You use it through a web page, which opens in the next step.

  The [Zenoh](/docs/systems/omx/specifications/software#middleware) setting lets Cyclo Intelligence talk to the robot's programs on this PC. The container comes with it, and part C only checks it.


</details>

<StepTab id="train-the-ai-model" need="Needs an NVIDIA GPU" title="Train the AI model" label="Train">

From this step on, the NVIDIA graphics card is needed, so check it first. Then turn your tries into a dataset and train ACT on it. Most of this step is waiting.

### A. Check the graphics card

In a PC terminal:

```bash
nvidia-smi
docker info | grep -i runtimes
```

Look for these two lines: your NVIDIA card, and `nvidia` in the `Runtimes` list. Only the left part of the card's line is shown. Your words and numbers can be different.

```text
|   0  NVIDIA GeForce RTX 4090        Off |
 Runtimes: runc io.containerd.runc.v2 nvidia
```

Both lines like this? Go on to part B. If not, open the box below first.

<OnlyIf title={<>Only if part A shows <code>not found</code>, <code>failed</code>, or no <code>nvidia</code></>}>

#### Install the graphics driver

Do this if `nvidia-smi` says `not found` or `failed`. Use these steps from [Ubuntu's guide](https://documentation.ubuntu.com/server/how-to/graphics/install-nvidia-drivers/), not the command the terminal suggests. First bring Ubuntu up to date.

```bash
sudo apt update && sudo apt upgrade
```

If it asks `Do you want to continue? [Y/n]`, press **Enter**. Restart the PC. Then install the driver that fits your card.

```bash
sudo ubuntu-drivers install
```

Restart the PC again. Then do part A again.

#### Let Docker use the card

Do this if `nvidia` is not in the `Runtimes` line. It installs the NVIDIA Container Toolkit with the commands of [NVIDIA's guide](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html). Paste one box at a time, and wait until you can type again.

```bash
sudo apt-get update && sudo apt-get install -y --no-install-recommends \
   ca-certificates \
   curl \
   gnupg2
```

```bash
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg \
  && curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
    sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
    sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
```

```bash
sudo apt-get update
sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

Then do part A again.

</OnlyIf>

### C. Stop the arms

The arms are not needed while the AI learns.

<Caution>

Lower the follower's gripper onto the table first. The follower goes limp when its program stops.

</Caution>

Press **Ctrl + C** in Terminals 4, 3, 2 and 1.

### D. Start the AI program

Open a new terminal with **Ctrl + Alt + T**, and paste. The first time, this builds the AI program on your PC. Many lines go by, and it takes a long while. Wait until you can type again.

```bash
cd ~/cyclo_intelligence
./docker/container.sh start-lerobot
```

When you can type again, ask whether it is running.

```bash
docker ps --filter name=lerobot_server --format "{{.Names}}: {{.Status}}"
```

Look for `Up`. The time can be different.

```text
lerobot_server: Up 1 minute (healthy)
```

### E. Train

In the same terminal, enter the AI program's container.

```bash
./docker/container.sh enter-lerobot
```

Then paste the training command. You do not need to change anything in it.

```bash
lerobot-train \
  --dataset.repo_id=local/stack_box \
  --dataset.root=/workspace/lerobot/Task_1_stack_box_MCAP_lerobot_v30 \
  --policy.type=act \
  --policy.chunk_size=50 \
  --policy.n_action_steps=50 \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --wandb.enable=false \
  --batch_size=8 \
  --steps=60000 \
  --save_freq=20000 \
  --output_dir=/workspace/model/lerobot/act_stack_box \
  --job_name=act_stack_box
```

Lines with `step:` go by while it learns. Wait until it ends. How long it takes depends on your graphics card.

### You should see

The last line is `End of training`. Your date and time are different.

```text
INFO 2026-11-12 14:02:11 ot_train.py:651 Checkpoint policy after step 60000
INFO 2026-11-12 14:02:12 ot_train.py:737 End of training
```

<NotGood id="train-the-ai-model-fix">

| You see | Do this |
| --- | --- |
| `NVIDIA-SMI has failed` after installing the driver | Restart the PC once more. If it stays, see [Ubuntu's guide](https://documentation.ubuntu.com/server/how-to/graphics/install-nvidia-drivers/). |
| `permission denied`, or no `Runtimes` line | Docker does not run without sudo yet. Do [Manage Docker as a non-root user](https://docs.docker.com/engine/install/linux-postinstall/#manage-docker-as-a-non-root-user) in Docker's guide. Then log out of Ubuntu and log in again. |
| `Could not get lock` | Ubuntu is updating itself. Wait a few minutes, then paste the same lines again. |
| `No such file or directory` with `lerobot_v30` | The dataset is not there. Do part B again and wait until it is done. |
| `already exists and resume is False` | You trained before. Paste the training command again with `act_stack_box` changed to `act_stack_box_2`, in both places. |
| `CUDA out of memory` | Close other programs that use the graphics card, then paste the training command again. |
| `Error: initialize cyclo_brain/policy/lerobot submodules` in part D | The LeRobot source is not downloaded. Paste the `git submodule` command of [Step 1, part A](#install-cyclo-intelligence), then do part D again. |
| `lerobot_server is not running` | Part D did not finish. Do part D again. |
| `no space left on device` in part D | The build needs more free disk. Free some, then do part D again. |

</NotGood>

<details>
  <summary>How does it work?</summary>

  The graphics driver lets Ubuntu use the card. The NVIDIA Container Toolkit lets the programs inside Docker use it too. The AI program runs in Docker, so it needs both. The commands in the box of part A are copied from Ubuntu's and NVIDIA's guides. If they change their commands, their pages linked above have the new ones.

  The model is named ACT. It looks at the camera picture and the arm's angles, and learns which moves you made next. It goes through your tries many times: 60,000 small learning steps.

  The result is saved in `~/cyclo_intelligence/docker/workspace/model/lerobot/act_stack_box`.

</details>

<details>
  <summary>How does it work?</summary>

  Many times a second, the model looks at the camera picture and the arm's angles, and plans the next few seconds of moves. With **3D Sim Deploy**, the plan only shows in the 3D picture. With **Real Robot Deploy**, it goes to the motors.

  The model has no "done" signal. It keeps going until you click **Stop**.

</details>

<StepTab id="make-it-work-better" title="Make it work better" label="Improve" extra>

This part is for after your first run, if you want OMX to do the task better.

How well imitation learning works depends on many things: what the camera sees, the light and the things around the robot, and how many tries you recorded and how alike they are. A second camera can also help. The camera on the wrist sees only what is in front of the gripper, and LeRobot, which trains the model in this guide, suggests two camera views.

### A. What the camera should see

OMX decides each move from the camera picture. So when it runs, the picture should look like it did when you recorded. You should be able to do the task by only looking at the picture. With one camera on the wrist, the picture can show no box at the start: the box should come into it as the gripper moves near.

### B. Other usual reasons

These are the usual reasons, not all of them. A model can also miss for other reasons, such as how many tries you recorded or how it was trained. They come from the [LeRobot guide](https://huggingface.co/docs/lerobot/en/il_robots#tips-for-gathering-data) and its list of [what makes a good dataset](https://huggingface.co/blog/lerobot-datasets#what-makes-a-good-dataset).

| What went wrong | What to do |
| --- | --- |
| The scene changed after you recorded | Run OMX in the same place, with the same things around it, as when you recorded. |
| Your tries were not alike | Start every try from the same pose, and pick up the same box the same way. Discard odd tries. |
| The boxes were in too many places | Keep them in the same places at first. Add other places only after it works well, with about 10 tries at each. |
| The camera shakes | Fix the camera firmly. |

Fix what went wrong. If it was your tries, record them again. Then do [Train the AI model](#train-the-ai-model) and [Run the AI model](#run-the-ai-model) again.

Still missing? Record more tries, or ask on [Discord](https://discord.gg/robotis).
