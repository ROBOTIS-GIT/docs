# Cannot Connect to the Robot

Follow these steps if you cannot connect to the robot through SSH, Cyclo Manager, or Cyclo Intelligence.

<SectionCard>

## 1. Check the Network Connection

Connect your User PC to the same router as the robot. You can use either a wired LAN connection or Wi-Fi.

<Tabs>
<TabItem value="sg2-w2" label="SG2 / W2">

Connect your PC to the robot's built-in router. The router normally uses `192.168.6.1`, and the robot's AGX Orin is configured with the fixed address `192.168.6.2/24`.

</TabItem>
<TabItem value="bg2-w1" label="BG2 / W1">

Connect the robot and your PC to the same external router. The router address and login details depend on the router.

</TabItem>
</Tabs>

</SectionCard>

<SectionCard>

## 2. Check for a Network Conflict (SG2 / W2)

Check the IP address and default gateway of the User PC's connection to the robot's built-in router. On Ubuntu, use:

```bash
ip -4 addr
ip route | grep default
```

With the normal configuration, the PC has a `192.168.6.x` address and the router's gateway is `192.168.6.1`. Check the address for the interface connected to the robot; a PC can have more than one network connection.

If the PC is on a different network and an external network is connected to the robot's WAN port, check whether that external network also uses `192.168.6.x`. When the networks overlap, the built-in router can change its LAN address. The AGX Orin remains at `192.168.6.2`, so the PC may no longer be able to reach it. A different PC address alone does not confirm a conflict.

</SectionCard>

<SectionCard>

## 3. Restore the Built-in Router Network (SG2 / W2)

If the built-in router's LAN address changed because of a network conflict, restore it as follows:

1. Disconnect the external LAN cable from the robot's **WAN** port. Disconnecting the cable does not automatically restore the router's LAN settings.
2. Connect your PC to the robot's Wi-Fi. Open the built-in router's administration page in a browser using the PC's **current default gateway** address.
3. Sign in using the robot's full serial number as both the ID and password. For example, if the serial number is `SNPR48A0000`, use `SNPR48A0000` for both.
4. Change the router's LAN address to `192.168.6.1` with subnet mask `255.255.255.0` (`/24`). Configure its DHCP pool to assign addresses in `192.168.6.x`, excluding `192.168.6.2`, which the AGX Orin uses.
5. After applying the settings, reconnect your PC to the robot's Wi-Fi and check that it receives a `192.168.6.x` address.

If you reconnect the WAN cable, use an external network that does not overlap with `192.168.6.0/24`. Otherwise, the conflict can happen again.

</SectionCard>

<SectionCard>

## 4. Verify the Connection

Check the router's connected-device list for the AGX Orin and confirm its IP address. Then test the connection directly; an entry in the list alone does not confirm that SSH or a service is working.

For SG2 and W2, try connecting to the robot's fixed IP address:

- **SSH:** `ssh robotis@192.168.6.2`
- **Cyclo Manager:** `http://192.168.6.2:3000`
- **Cyclo Intelligence:** `http://192.168.6.2:7080` when Cyclo Intelligence is running on the robot PC and uses the default port.

For BG2 and W1, find the AGX Orin's IP address in the external router's connected-device list and use that address instead. If IP access works but the hostname does not, see [Robot PC Access](/docs/systems/aiworker/quick_start_guide/advanced/robot_pc_access#if-the-hostname-is-not-available).

</SectionCard>

<SectionCard>

## 5. If the Robot Still Cannot Be Reached

If the robot still cannot be reached, check its connection to the router. The AGX Orin may not have booted correctly; restart the robot, allow it to finish booting, and try again.

</SectionCard>
