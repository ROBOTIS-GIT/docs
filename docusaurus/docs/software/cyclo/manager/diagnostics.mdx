# Diagnostics

Use Diagnostics to check robot devices and camera streams.

- **Robot** checks DYNAMIXEL devices, sensors, and controllers.
- **Camera** checks camera streams.

:::info

The AI Worker container must be running with a compatible s6 agent and diagnostic software. If the agent is incompatible, follow the [Agent Update](/docs/software/cyclo/manager/dashboard#agent-update) instructions.

:::

:::warning

Stop robot and leader bringup before starting a check. Stop all diagnostic checks before starting bringup. During a robot check, do not run another program that communicates with the same devices.

:::

![Diagnostics page with Robot and Camera tabs and the robot map](/img/software/cyclo/manager/diagnostics/diagnostics_overview.png)

## Robot Diagnostics

Robot Diagnostics checks the hardware status of DYNAMIXEL devices, sensors, and controllers configured for the selected robot type.

### What Is Checked

Robot Diagnostics uses the selected robot type's Xacro configuration to identify the DYNAMIXEL devices, controllers, and sensors to check.

The check verifies:

- Whether the configured ports can be opened.
- Whether each device responds and reports supported status information.

Depending on the device model, readings can include hardware errors, voltage, temperature, and supported board data. Additional devices may be identified without a full diagnostic read.

Expand **Connection settings** to review the configured devices, ports, and baud rates.

- **Details** shows the device names and IDs for a connection.
- **Change** lets you use a different port or baud rate for the check.

Changes apply only to the check; they do not modify the Xacro or device settings.

![Robot type and expanded connection settings with Checklist, Change, and Details](/img/software/cyclo/manager/diagnostics/connection_settings.png)

### Robot Map and Device List

Select **Start check** to begin and **Stop check** to end the check.

:::info

If no Diagnostics page remains connected, the check stops after approximately five seconds without a connection signal. Reconnecting within that period keeps it running.

:::

Use **Robot map** or **Device list** to view device status. Select a device in either view to see its details.

### Device Status

Each marker shows the current status of its device. Select a marker for details.

| Status | Meaning |
| --- | --- |
| <StatusIcon symbol="✓" color="#89d185" /> **Healthy** | The device responds and its required diagnostic readings indicate no issue. |
| <StatusIcon symbol="!" color="#cca700" /> **Warning** | A DYNAMIXEL temperature is within 5 °C below its configured limit, or a Y-series device reports error code 9, the multi-turn battery warning. |
| <StatusIcon symbol="!" color="#f48771" /> **Error** | The device reports a hardware error or alert, its voltage is outside its configured limits, its temperature reaches or exceeds its configured limit, or its detected model differs from the configured model. A supported board's nonzero error code is also treated as an error. |
| <span style={{whiteSpace: 'nowrap'}}><StatusIcon symbol="!" color="#f0a663" /> <strong>Communication Error</strong></span> | The port cannot be opened or maintained, the device does not respond to PING, or a register read fails. |
| <StatusIcon symbol="?" color="#75beff" /> **Unknown** | The device responds, but its health cannot be determined. Examples include an unavailable model definition, unsupported board readings, or missing required readings or limits. |
| <StatusIcon symbol="·" color="#989898" /> **Not checked** | The device is waiting to be checked or could not be checked through its hand controller. |
| <StatusIcon symbol="◷" color="#75beff" /> **Stale data** | During an active check, the last response or a required board reading is missing or more than three seconds old. |

A communication failure does not by itself establish that the device hardware is faulty. **Unknown** and **Not checked** do not mean the device is healthy.

## Camera Diagnostics

Camera Diagnostics detects connected RealSense and ZED cameras and checks whether their color and depth streams are receiving frames.

### Camera Discovery and Status

Select **Start check** to discover connected RealSense and ZED cameras supported by the installed SDKs. Each camera appears as it is found. Select a camera to view its stream, and select **Stop check** to end the check.

:::info

If no Diagnostics page remains connected, the check stops after approximately five seconds without a connection signal. Reconnecting within that period keeps it running.

:::

Each camera card shows its name, serial number, and status. **Streaming** means frames are being received. For an error, select the camera and review its message.

To find a camera connected after the check started, stop and restart the check.

![Camera check with detected cameras and the selected stream](/img/software/cyclo/manager/diagnostics/camera_stream.png)

### Color and Depth

Select **Color** or **Depth** above the preview to change the displayed stream when available. Both streams are requested at startup. Other detected cameras continue to be monitored when they are not selected.

The depth preview is a colorized visualization, not a distance measurement or depth-accuracy test. The check verifies frame reception; it does not verify ROS topic delivery or image quality.

![Camera check showing the Depth stream](/img/software/cyclo/manager/diagnostics/camera_depth.png)

### Frame Rate and Stream Information

| Display | Meaning |
| --- | --- |
| **Camera FPS** | Camera frame rate reported or estimated from available camera timing information. A dash means it is unavailable. |
| **Received FPS** | Frame rate received by the diagnostic worker for the selected stream. |
| **Configured FPS** | Frame rate of the selected stream configuration. |

The preview can also show the serial number, USB connection and resolution when available. Browser display rate can be lower than the received rate because of encoding, network, or browser performance.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| **Start check** is unavailable | Stop bringup and check the AI Worker agent connection. Follow any update or connection message displayed on the page. |
| Port connection failed | Check the port path, device permissions, USB connection, power, and whether another process uses the port. Restart the check after reconnecting a disconnected port. |
| No PING response | Check device power, wiring, ID, and baud rate. A missing response does not identify the failed component by itself. |
| Register read failed | Check communication and device connections. The device may have responded to PING even though a subsequent read failed. |
| Model mismatch or unavailable definition | Inspect the expected and detected models and the displayed model definition message. These conditions are independent. |
| Camera missing or stream error | Check power, connection, installed SDK, and whether another process uses the camera. Restart the check after reconnecting it. |

</SectionCard>



:::note

Checks started directly from a terminal are managed separately.

:::
