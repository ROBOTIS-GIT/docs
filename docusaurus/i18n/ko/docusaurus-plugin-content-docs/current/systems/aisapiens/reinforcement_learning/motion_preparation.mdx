# Motion 준비

학습 방법을 고르기 전에 로봇 reference를 준비합니다. 사람 모션 복원, retargeting, 학습 motion, policy checkpoint, 배포 자산은 서로 다른 산출물입니다.

## 1. Source 생성과 Retargeting

목적에 맞게 [Kimodo](/docs/systems/aisapiens/motion_generation_retargeting/kimodo/), [GEM-X](/docs/systems/aisapiens/motion_generation/gem-x/), [FlowHMR](/docs/systems/aisapiens/motion_generation/flowhmr/)를 사용하고 대상 K1 revision으로 retargeting합니다.

- [Soma-retargeter](/docs/systems/aisapiens/motion_generation_retargeting/soma_retargeter/)의 headered K1 CSV는 기존 converter recipe의 입력입니다.
- [UMR](/docs/systems/aisapiens/motion_generation_retargeting/umr/)의 qpos NPZ는 Soma CSV나 Cyclo 학습 archive가 아닙니다. 별도로 검증된 adapter가 필요하며 확장자 변경은 변환이 아닙니다.

원본 motion, 실제 FPS, 모델 revision, 변환 설정을 보존하세요. 발 접촉·크기·방향·관절 한계·속도·loop 연결을 확인하고 모션과 body-model 라이선스를 준수합니다.

## 2. 플랫폼 Reference 생성

| 플랫폼 | 변환 및 task 설정 | Reference 위치 |
| --- | --- | --- |
| Cyclo Lab | <a href="/docs/systems/aisapiens/reinforcement_learning/cyclo_lab/mimic#how-to-add-your-own-mimic-task">Lab motion/task recipe (영문)</a> | `source/cyclo_lab/data/motions/K1_rev1/<motion>/` |
| Cyclo MJLab | <a href="/docs/systems/aisapiens/reinforcement_learning/cyclo_mjlab/mimic#how-to-add-your-own-mimic-task">MJLab motion/task recipe (영문)</a> | `source/assets/motions/K1_rev1/<motion>/` |

원본 headered Soma CSV, 학습 NPZ, 배포 CSV를 구분해 보존합니다. 플랫폼별 loader에 맞는 schema인지 확인해야 하며 파일명이 같다고 같은 형식인 것은 아닙니다.

MJLab 컨테이너에서 변환한 NPZ를 다음과 같이 구조 검증할 수 있습니다.

```bash
python scripts/tools/motion/replay_npz.py \
  -f source/assets/motions/K1_rev1/my_motion/my_motion.npz \
  --validate-only
```

`my_motion`은 자신의 변환 motion 이름으로 바꿉니다. 구조 검사만으로 좋은 모션이 보장되지는 않으므로 play recipe로 실제 움직임도 확인하세요.

## 3. 검증된 Adapter를 통한 Reference 재사용

목표 사용자 계약은 같은 플랫폼의 기존 50 Hz Cyclo NPZ를 BeyondMimic과 SuperMimic에서 선택해 재사용하는 것입니다. SuperMimic용 표현 변환은 별도 사용자 데이터셋 대신 내부 adapter가 처리합니다. 두 플랫폼 개발 브랜치가 이 계약을 구현했으며 schema와 runtime 경계는 서로 다릅니다.

| 방법 | 입력 경계 |
| --- | --- |
| BeyondMimic | 플랫폼의 변환 NPZ와 task config를 사용합니다. joint/body 이름·순서, state 및 velocity 필드를 보존합니다. |
| Lab SuperMimic | 개발 selector에서 이름이 있는 동일한 50 Hz Cyclo Lab NPZ를 두 방법에 지정합니다. 명시적 quaternion metadata와 joint/body 검증 후 shared loader 및 Isaac-native bridge로 연결합니다. [Lab 명령](./cyclo_lab/supermimic)을 따르며 별도 research-MJLab 변환은 필요하지 않습니다. |
| MJLab SuperMimic | 개발 브랜치에서 기존 50 Hz Cyclo/MuJoCo NPZ를 직접 지정합니다. 내부 adapter가 이름이 있는 body/joint state, wxyz quaternion, FK 및 지원하는 COM velocity profile을 검증하고 research loader로 전달합니다. Isaac/xyzw 입력은 거부합니다. [MJLab 명령](./cyclo_mjlab/supermimic)을 따르며 별도 수동 변환은 필요하지 않습니다. |

각 경계에서 단위(m, rad 및 시간 미분), quaternion 순서, root frame, sample rate, finite 값을 확인합니다. 해당 motion tool로 resampling하고 FPS 필드만 바꾸지 마세요. 좌표 변환을 두 번 적용하지 않습니다.

Reference 재사용은 Lab/MJLab 배열의 직접 호환이나 PPO/world-model policy의 배포 호환을 뜻하지 않습니다. 선택한 로봇·reference에 대해 backend별 loader와 adapter를 검증해야 합니다.

## 4. Motion과 Checkpoint 연결

Reference 파일을 task·learner·runtime·모델 revision·checkpoint와 함께 기록하고 play/export에도 같은 reference를 사용합니다. BeyondMimic 배포에서는 같은 실행의 `policy.onnx`, `sim2real.yaml`, motion CSV를 함께 준비합니다. SuperMimic은 별도 export/controller 계약이 필요합니다.
